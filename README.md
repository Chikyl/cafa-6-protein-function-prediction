# 🧬 CAFA 6 — Protein Function Prediction

Predicting **Gene Ontology (GO) terms** from protein sequences for the [CAFA 6 Protein Function Prediction](https://www.kaggle.com/competitions/cafa-6-protein-function-prediction) Kaggle competition.

Each protein can carry many functional labels (molecular function, biological process, cellular component), so the task is framed as **multi-label classification**. This repository compares several protein representations — pretrained language-model embeddings and hand-engineered sequence features — all fed to the same residual MLP classifier.

## 🔬 Approaches

| Notebook | Representation | Input dim | GO labels | Source of features |
|---|---|---|---|---|
| `cafa-6-protbert` | [ProtBERT](https://huggingface.co/Rostlab/prot_bert) (mean-pooled) | 1024 | 200 | Generated by the embeddings notebook |
| `cafa-6-esm` | ESM-2 3B | 2560 | 500 | Precomputed Kaggle dataset |
| `cafa-6-t5` | T5 protein language model | 1024 | 500 | Precomputed Kaggle dataset |
| `protein-function-protlearn-features` | [ProtLearn](https://protlearn.readthedocs.io/) descriptors | 695 | 500 | Computed with ProtLearn |

### ProtLearn feature breakdown (695-d)

| Group | Dims |
|---|---|
| Sequence length | 1 |
| Amino acid composition (AAC) | 20 |
| Dipeptide composition | 400 |
| Shannon entropy | 1 |
| CTD — composition / transition / distribution | 273 |

Non-standard residues are cleaned before extraction: `U→C`, `B→D`, `Z→E`, `X` removed.

## ⚙️ Pipeline

1. **Embeddings** — sequences are parsed from FASTA (Biopython). ProtBERT inputs are space-separated amino acids, truncated to 1000 tokens, and mean-pooled over the sequence dimension (batch size 128, mixed precision on GPU).
2. **Label preparation**
   - Load `train_terms.tsv` and group GO terms per protein.
   - **Propagate ancestors** through the GO graph (`go-basic.obo`, via `obonet` + `networkx`) so each protein carries all parent terms.
   - Keep the **top-N most frequent GO terms** (N = 200 for ProtBERT, 500 for the others) and binarize with `MultiLabelBinarizer`.
3. **Model** — residual MLP:
   `Linear → BatchNorm → ReLU → Dropout(0.3)` blocks with hidden sizes `[1024, 512, 512]`, a skip connection added every second block (when shapes match), and a linear output layer.
4. **Training** — Adam (lr 1e-3), `ReduceLROnPlateau` (factor 0.5, patience 2), 90/10 train/validation split (seed 42), batch size 128, up to 100 epochs with early stopping (patience 15) on validation loss. Metric: `MultilabelF1Score` from TorchMetrics.
5. **Inference** — sigmoid over logits, per-protein predictions sorted by confidence, capped at 1500 terms, probabilities rounded to 3 significant figures, written as `submission.tsv` (`EntryID \t GO term \t score`).

## 🚀 Getting Started

The notebooks are written for **Kaggle** (paths like `/kaggle/input/...`) and expect these inputs:

- Competition data: `cafa-6-protein-function-prediction` (`train_terms.tsv`, `go-basic.obo`, `train_sequences.fasta`, `testsuperset.fasta`, …)
- Embedding datasets (for the training notebooks): ProtBERT, ESM-2 3B, and T5 embeddings, each with matching `*_ids.npy` files

### Dependencies

```bash
pip install torch torchmetrics transformers biopython obonet networkx \
            scikit-learn pandas numpy matplotlib tqdm protlearn
```

### Run order

1. *(Optional)* Run `Embeddings generation/cafa-6-protbert-embeddings.ipynb` to produce `train_ids.npy` / `train_embeds.npy`. The test-set block is commented out in the notebook — uncomment it to embed the test superset (this is slow: ~3 h on a Kaggle GPU for the training set alone).
2. Attach the relevant embedding dataset and run the matching notebook in `Training notebooks/`.
3. Submit the generated `submission.tsv`.
